## Acceptance workflow failure

Run with `CLAUDE_OPENCODE_E2E=1 CLAUDE_OPENCODE_E2E_WORKFLOW=1`, no `CLAUDE_OPENCODE_E2E_MODEL`
(so OpenCode's own default model was used):

```
x fixes the demo project through a full multi-agent workflow  420008ms
Error: Test timed out in 420000ms.
```

The whole workflow (four `delegate_task` calls plus several `npm test` runs) has a single 420 s budget
(`TIMEOUT` in `tests/e2e/demo-workflow.test.ts`). It did not finish within that budget.

**Follow-up run (same day):** the same workflow with `CLAUDE_OPENCODE_E2E_MODEL=nan/deepseek-v4-flash`
passed in 148 s (a single prompt to that model answers in about 3 s). The workflow therefore completes
end to end through the bridge (researcher -> coder -> reviewer -> tester, tests green, diff reported);
the 420 s timeout came from the slow default model. I did not time the default model per step, so the exact
slow step is unknown, but no bridge defect was observed.

## Suggested follow-ups

- Run the workflow with an explicit fast model (`CLAUDE_OPENCODE_E2E_MODEL=nan/deepseek-v4-flash` works); `opencode models` lists the 23 available.
- Add per-step logging (or a per-step timeout) to the workflow test so a timeout identifies the stuck agent.
- Consider raising `TIMEOUT` if slow hosted default models are expected.
